Make platform changes small, checked and reversible.

Build only what a change can break. Refuse a change plan that has no rollback. Run a service behind a load balancer with TLS and a deploy that undoes itself. Python and Terraform, checked in CI.

Build less, trust it more

A monorepo CI selector. A change to a shared library builds its dependents in order. A docs change builds nothing.

Changes with a way back

A plan needs an owner, an announcement, and for every step a check and a rollback. Production cannot come before staging.

A service that heals a bad deploy

ECS behind an ALB: TLS 1.3 policy, private tasks, health checks, circuit-breaker rollback, alarms with runbooks.

Reject the risky plan before work starts

A change plan is a short TOML file. The checker refuses the shapes that cause bad nights. Real output from the repo:

A plan that passes 
$ pck check examples/plans/https-only-listener.toml
plan ok
The same plan, failing in staging 
$ pck simulate ... --fail-at staging-listener
apply     dev-listener (dev)
check     dev-listener
ok        dev-listener
apply     staging-listener (staging)
check     staging-listener
FAILED    staging-listener
rollback  staging-listener (staging)
rollback  dev-listener (dev)
result    rolled back, nothing left half-applied
A plan that does not 
$ pck check examples/plans/big-bang.toml
ERROR   change: notify list is empty
ERROR   change: announce_hours_before must be at least 1
ERROR   step everything-in-prod: prod step with
        no earlier step in dev, staging
ERROR   step everything-in-prod: touches 10
        resources, limit is 5: split it
ERROR   step everything-in-prod: rollback is none
        but the step is not marked irreversible
WARNING step everything-in-prod: no soak_minutes
plan rejected

A good plan also renders a runbook and a short heads-up message: pck runbook, pck announce.

ECS behind an ALB, with the boring parts done

One Terraform module. terraform fmt and terraform validate pass in CI.

TLS and the edge

HTTPS listener on a TLS 1.3/1.2 policy, port 80 only redirects, invalid headers dropped, optional access logs.

Private by default

Tasks in private subnets, reachable only from the load balancer. The app role starts with no permissions.

Safe deploys

Never below full capacity, two or more tasks, and a circuit breaker that rolls back when new tasks keep failing.

Alarms with runbooks

5xx, unhealthy targets and low task count, each pointing at a runbook in the repo.

  • runbooks: 5xx, unhealthy tasks, rolling back a change

What this is not

It is a lab. The Terraform is validated, not applied. The commands inside example plans are printed, never run. It is not certified for HIPAA, HITRUST or anything else and has not touched real health data: docs/controls.md says what it could show a compliance team and what it could not.
